**Português**
- Melhorado: o motor de sugestões agora é **só C++**. A busca de correção (letra trocada, faltando, a mais, troca de lugar, espaço faltando) e a leitura dos trigramas (previsão a partir das duas palavras anteriores) deixaram de ter uma cópia em Java no app. Nos testes o resultado é o mesmo de antes: na amostra de frases de legendas separada para teste, a palavra certa aparece entre as 3 sugestões em 14,3% dos casos depois do espaço e em 67,9% com 3 letras digitadas (inglês), sem diferença para a versão anterior; as verificações de estratégia das três línguas passam.
- Melhorado: a biblioteca nativa passa a carregar em segundo plano assim que o teclado abre o dicionário, e não mais na primeira tecla. Antes, as primeiras teclas depois de o processo nascer usavam a cópia em Java enquanto a biblioteca carregava; agora, se uma tecla chegar antes do fim, ela espera. No PC o carregamento leva 0,3 ms e preparar as tabelas leva de 8 a 14 ms; no celular não foi medido.
- Melhorado: o código do app encolhe cerca de 8 KB, e os testes deixam de rodar a mesma coisa duas vezes (uma com o motor nativo e outra com o Java).
- Melhorado: nas configurações, a linha "Motor de sugestões" mostra "Nativo (C++)" ou, se a biblioteca não carregar, "Indisponível (biblioteca nativa não encontrada)". Nesse caso raro o teclado continua digitando, completando palavras e prevendo a partir do par de palavras do dicionário, mas fica sem a correção por busca e sem a previsão de duas palavras.
- Observações: a mistura por probabilidade de trigramas, bigramas e frequência para a previsão depois do espaço foi testada nas três línguas (legendas, conversa e notícias) e perdeu de 0,8 a 2,4 pontos para o bônus fixo de trigrama, que já estava no melhor ponto; por isso a previsão não mudou. Nenhuma outra parte do código em Java pesava na tecla: em uma medição do caminho da tecla, mais de 99% do tempo estava nas bibliotecas nativas. As bibliotecas nativas não mudaram nesta versão e os pacotes de dicionário continuam os da 1.86.1.

**English**
- Improved: the suggestion engine is now **C++ only**. The correction search (swapped, missing and extra letters, transpositions, missing space) and the trigram reader (prediction from the two previous words) no longer have a Java copy in the app. In the tests the result is the same as before: on the sample of subtitle sentences set aside for testing, the right word is among the 3 suggestions in 14.3% of the cases after the space and in 67.9% with 3 letters typed (English), with no difference from the previous version; the strategy checks of the three languages pass.
- Improved: the native library now loads in the background as soon as the keyboard opens the dictionary, not on the first key. Before, the first keys after the process started used the Java copy while the library loaded; now a key that arrives before the load ends waits for it. On the PC the load takes 0.3 ms and preparing the tables takes 8 to 14 ms; it was not measured on a phone.
- Improved: the app code shrinks by about 8 KB, and the tests no longer run the same thing twice (once with the native engine and once with Java).
- Improved: in the settings, the "Suggestion engine" line shows "Native (C++)" or, if the library does not load, "Unavailable (native library not found)". In that rare case the keyboard still types, completes words and predicts from the dictionary's word pairs, but has no correction by search and no two-word prediction.
- Notes: a mix by probability of trigrams, bigrams and frequency for the prediction after the space was tested in the three languages (subtitles, chat and news) and lost 0.8 to 2.4 points to the fixed trigram bonus, which was already at its best; so the prediction did not change. No other Java code weighed on the key press: in a measurement of the key path, more than 99% of the time was in the native libraries. The native libraries did not change in this version and the dictionary packs are still those of 1.86.1.
