**English**
- Fixed: on Android 17, the large fixed gap below the Settings title (and the subscreens) is gone, both still and while scrolling. The margin for the system bars and the camera cutout is now applied once. From Android 8 to 14 the classic mode (bars in the theme's color) stays as it was.
- Fixed: tapping the keyboard's gear several times opened several copies of Settings, and Back needed several taps; a double tap on a Settings row opened the subscreen twice. Now the screen that is already open comes to the front, without closing what is on top of it (a style being edited, for instance).
- Fixed: Back on a screen opened from the keyboard (Settings, Packs, Sheets, AI Editor and styles) sometimes landed on the app's main page instead of returning to the app you were typing in. Each of these screens now has its own task and shows as a separate card in recent apps.
- Fixed: on Android 17 the keyboard did not come back after rotating the screen in the editors. Now, in the AI style editor and the Sheets editor (test field), it returns in the same field, with the cursor in the same place, and the instructions field stays above the keyboard.
- Fixed: rotating the screen in the AI style editor erased the name and instructions you had typed. Now the text, the emoji and a pending **Delete** survive the rotation, and opening another style from the dialog does not lose what is being edited.
- Fixed: when coming back from Settings to the AI Editor, the keyboard and the dialog reappear in the field you left, and not only when the system happened to bring the keyboard back by itself. It applies to the same app, once per trip and up to 2 minutes after leaving.
- Fixed: the **Customize keyboard** tool closed when the screen rotated. Now the panel opens inside the keyboard in landscape and the dialog returns in portrait, without the keyboard closing; on Android 17 the keyboard is also asked back. With the tool closed, rotating opens nothing.
- Fixed: in landscape, the AI Editor dialog sat under the status bar and the camera, and when the keyboard took almost the whole screen only the header showed. Now the card respects the bars and the cutout and, if the area above the keyboard is small (under 240 dp), the dialog uses the whole screen.
- Improved: any button of the tool bar closes the open AI Editor or Customize keyboard dialog and then does what it always did (opens the panel, the translator, etc.).
- New: **Hardware acceleration** option in Advanced, in the **Screens** category. Off by default: the app's screens are drawn by the processor. On, they use the GPU, with more memory. It does not affect the keyboard and goes back to off in **Restore defaults**. Some systems, like the ROM of a Xiaomi running Android 13 that we tested, already draw on the GPU anyway, and there the option changes nothing.
- New: the **Keyboard drawing** and **Drawing of this screen** rows (read-only) in Advanced show whether the keyboard window and the current screen are drawn by the GPU or by the processor, and whether the app asked for it or the system turned it on by itself. With adb, the same answer is in `adb logcat -s MrAccel`.
- Improved: the app now targets Android 17 (targetSdk 37). Nothing changes in use, with one exception: on Android 17, an AI Editor endpoint on a machine of your local network (private IP or `.local` name) stops connecting, because the system requires the local network permission and the app does not ask for it. Services on the internet (OpenAI, Groq, OpenRouter, Gemini and similar) are not affected.
